WHAT THIS PROJECT IS
--------------------------------------------------------------------------------
isabelle-query is a zero-dependency, stdlib-only Python tool (`query` CLI) that
indexes Isabelle/Isar theory files by REGEX — it parses outer-syntax command
structure (theorem/lemma/definition/...) WITHOUT running Isabelle, so it stays
fast (~4 s over the whole AFP) and needs no Isabelle install. It powers commands
like `show`, `largest`, `callers -r`, `callees`, `sorry`, `unused`.

Call graph (cli.py: _build_call_graph): replaced the O(lines x names) per-name
boundary search (which made `callers -r`/`callees` over the AFP take TENS OF
HOURS) with a single linear tokenise-and-hash pass (~25 s over the AFP). It
extracts three token shapes per line and intersects with the name set:
    sym_re   = (?:\\<\^?\w+>|[\w'])+   (symbolic identifiers, must match SYM_NAME_RE)

oracle hits on short symbolic names nested in longer identifiers). The test

THE OPEN THREAD — IMPLEMENT A FAITHFUL CUSTOM-COMMAND KEYWORD SCANNER  (do this)
--------------------------------------------------------------------------------
Biggest remaining gap: custom outer-syntax commands like AOT's `AOT_theorem`
(1,024 uses), `AOT_define`, `AOT_axiom`, `AOT_act_theorem` are NOT recognized,
so those facts are unindexed AND they inflate the spans of the few recognized
entries near them (e.g. `beta-C-cor:3` reports a 3867-line span).

KEY INSIGHT (verified against the real parser): the one thing the regex tool
can't otherwise know — that `AOT_theorem` is a theorem command — is declared as
PLAIN TEXT in theory headers, and that declaration IS Isabelle's keyword table.
So scanning it is FAITHFUL, not heuristic. (This supersedes the `<Prefix>_theorem`
name-guess heuristic the user previously declined.)

Evidence — AOT/AOT_commands.thy:4-26:
    keywords "AOT_define"       :: thy_decl
         and "AOT_theorem"      :: thy_goal
         and "AOT_lemma"        :: thy_goal
         and "AOT_act_theorem"  :: thy_goal
         and "AOT_axiom"        :: thy_goal ...

Grammar (Isabelle2025-2, Pure/Thy/thy_header.ML:149-164):
    keyword_decl  = repeat1(quoted_name) , optional( "::" kind (load)? (% tag)* )
    keyword_decls = and_list1(keyword_decl)         -- 'and'-separated
    A decl with NO "::" kind is a MINOR keyword (syntax), NOT a command — skip it.
    Several names may share one spec: `keywords "a" "b" :: thy_decl`.

Authoritative kind -> family map (Pure/Isar/keyword.scala):
    theory_goal = { thy_goal, thy_goal_defn, thy_goal_stmt }   (line 93) -> THEOREM/LEMMA family (has a proof)
    theory_defn = { thy_defn, thy_goal_defn }                  (line 76) -> introduces a definition
    thy_decl / thy_decl_block / thy_stmt                                 -> declaration family
    (thy_goal_defn is BOTH: defines + proves, e.g. `function`. Tag pragmatically.)
The global keyword table = UNION of every header's declarations (keyword.scala:151
`Keywords.++`) — so "scan all headers once, build one table" mirrors Isabelle exactly.

Scale: 129 AFP theories declare custom keywords. Kinds seen across the AFP:
    thy_decl 91, thy_goal 26, thy_defn 17, thy_goal_stmt 10, thy_goal_defn 2,
    thy_decl_block 2, thy_load 6, qed_block 1.

IMPLEMENTATION SKETCH:
  1. Add a header-scanner: for each .thy under the active root, read the
     `keywords ... begin` clause and parse name(s) :: kind, building a dict
     {command_name: family} where family in {THEOREM-like, DEF-like}. Skip
     names with no kind, and non-theory kinds (qed/prf/diag/document/thy_load).
  2. Feed that table into extract_entries. Two integration options:
       (a) build a per-run DECL_RE that alternates the scanned command names, or
       (b) after the fixed DECL_RE misses, check the line's first token against
           the scanned table.
     extract_entries(lines) currently takes only `lines`; you'll need to thread
     the table in (param or a module-level set populated by load_index).
  3. Route recognized commands by family through the EXISTING name branches:
       thy_goal* -> the lemma/theorem branch (already handles quoted labels like
                    `AOT_theorem "betaC:1:b":` and the new robustness)
       thy_decl*/thy_defn -> the definition branch (handles `AOT_define Name ::`)
     Name extraction reuses _parse_name / the label rule — no new name logic.
  4. CAVEAT to honor: keywords are technically per-session; a flat global union
     could collide if two entries declare the same command with different kinds.
     Rare (names are distinctive); for a single project scan only its headers.
  5. Wire it as the fix for tests/test_known_failures.py::test_custom_fact_command_keyword
     (remove the @expectedFailure there once it passes). Re-run the full suite +
     corpus; confirm ? rate drops, AOT spans collapse, call-graph oracle parity
     still holds (added==0, drops<0.5%).
